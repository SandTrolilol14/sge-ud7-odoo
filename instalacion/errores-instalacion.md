# Registro de Errores de Instalación de Odoo

Durante el despliegue de **Odoo 19.0 Community** junto a **PostgreSQL 16** sobre Docker (gestionado mediante Dockge en un servidor casero Linux), se produjeron y resolvieron los siguientes errores reales:

| Error o mensaje en consola | Causa raíz | Solución aplicada | Fuente consultada |
| :--- | :--- | :--- | :--- |
| `grep: /etc/odoo/odoo.conf: No such file or directory` seguido de `configparser.NoSectionError: No section: 'options'` y salida con `code 1`. | Al mapear el volumen local `./config:/etc/odoo` en el archivo `compose.yaml` sin haber creado previamente el fichero en el host, Docker montó un directorio vacío que sobrescribió el archivo `odoo.conf` por defecto del contenedor. | Se creó manualmente el archivo `/opt/stacks/oodoo/config/odoo.conf` en el servidor host añadiendo la cabecera `[options]`, las credenciales de conexión a la BD (`db_host`, `db_user`, `db_password`) y la ruta `addons_path`. Además, se ajustaron los permisos de lectura con `chmod 644`. | Documentación oficial de la imagen de Odoo en Docker Hub y asistencia de IA (Gemini) para depuración de permisos de volúmenes en Linux. |
| `FATAL: database files are incompatible with server. The data directory was initialized by PostgreSQL version 15, which is not compatible with this version 16.15.` | Inicialmente se levantó el entorno probando PostgreSQL 15 y posteriormente se actualizó el `compose.yaml` a PostgreSQL 16 manteniendo el mismo volumen persistente (`odoo_db_data`), cuyos ficheros binarios internos eran incompatibles entre versiones mayores. | Se detuvo el stack y se eliminaron los volúmenes antiguos mediante el comando `docker compose down -v` para limpiar los datos residuales de la versión 15 y permitir que PostgreSQL 16 inicializara un clúster limpio desde cero. | Logs del contenedor `db`, documentación oficial de PostgreSQL sobre migración de versiones y consulta puntual a IA. |
